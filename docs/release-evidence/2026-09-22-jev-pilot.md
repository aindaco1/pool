## Frozen pilot

- 34 actual rendered cases: English/Spanish checkout pending/saved confirmation;
  active, deadline-locked, payment-failed, charged and cancelled pledge cards;
  confirmation, modification, cancellation, failure and charge emails in HTML
  and plain text.
- 16 labeled controls: faithful/flawed pairs covering pending confirmation,
  conditional charging, deadline locking and payment recovery in both languages.
- Each run: 50 requests, 68 atomic questions, resolved model `jev-1.13.0`.
- Provisional minimum probability margin 0.10. It is not calibrated for Pool.
- Same corpus SHA-256 in both runs: `186cddf6674c12bbc386c372abed579e1e05de9816d3ed769cccceb52261dd76`.
- All source and candidate hashes match across the two runs. No question, label,
  threshold, model allowlist or product-copy tuning between runs.

| Result | First run | Repeated run |

| Correct labeled controls | 16/16 | 16/16 |
| False passes / false failures on controls | 0 / 0 | 0 / 0 |
| Rendered cases passed | 33/34 | 32/34 |

| Input tokens | 28,386 | 28,386 |

The small controls do not establish judge accuracy on actual messages. The
pending-confirmation copy distinguishes a **saved payment method** from an
**unconfirmed pledge** and explicitly says there has been no charge. Source and
DOM inspection support that distinction; the exact capture also verifies that
success remains hidden until persistence is confirmed.

Jev marked the Spanish pending statement as failing in both runs (fail 0.83 and
0.81). The equivalent English statement changed from pass 0.57 / fail 0.43 to
pass 0.41 / fail 0.59. These appear to be judge false alarms caused by the
saved-card versus confirmed-pledge distinction. This is an engineering
interpretation of the retained text, not an independently labeled Spanish review.
The full distribution and actual candidate accompany each flag in `review.md`.

**Decision: retain the advisory workflow. Do not make these findings a merge or
release gate, change correct copy to satisfy the judge, or lower thresholds.**
The next calibration set should include this distinction, richer realistic
controls and fluent bilingual labels, with separate fresh validation.

Estimated inference: $0.001192212 per run, $0.002384424 total for the two runs,
based on the dated TypeSafe input estimate (not a provider billing receipt).
Each run reserved $0.091392 against the $0.25 estimate limit. No retries,
fallback, purchases or top-ups occurred. Only synthetic/public system copy was
sent; no real supporter records, tokens, account IDs or credentials were sent in
model payloads. No Stripe operation, email delivery or production read occurred.

## Ethical and release boundaries

This adds a development-only external text judge. Inputs are bounded synthetic
fixtures and public system text; arbitrary/custom inputs and production reads
are unavailable. Candidate text remains untrusted data, not instructions. Low
confidence and unknown model versions route to review. Gateway cache/logging
headers are disabled, without claiming provider zero retention. Existing exact
checks own money, permission and state correctness. This is DOM text evidence,
not layout, real-browser/provider acceptance or proof of Spanish fluency.
