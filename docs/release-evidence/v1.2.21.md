# Pool v1.2.21 — September 27, 2026

## Scope

This maintenance release collects the 185 commits between `v1.2.20`
(`9ca9dd098366e4030bdb2aae50a66e24ef15b6ef`) and the reviewed main revision
`c03a068e8b8ac7e87cb368311003d1c0704230fe`, plus the existing local Jev
charged-versus-saved controls and their regression test. It aligns the root and
Worker package/lock versions, canonical platform version/label, Worker provider
identity, README, and changelog at `1.2.21`.

The rollup adds no product feature or operational policy beyond those already
on main. The complete grouped change list is in [CHANGELOG](../../CHANGELOG.md).
No campaign, supporter, account, payment, or delivery record is changed by this
release preparation. Confirmed duplicate local files were moved recoverably out
of the checkout; canonical campaign drafts and media remain intact.

## Jev follow-up

The existing local changes add faithful/flawed charged-message pairs in English
and Spanish, increasing the synthetic controls from 16 to 20. The regression
checks both a faithful simulated judge and a judge that incorrectly accepts
saved-card wording in a charge confirmation. These simulations verify evaluation
wiring, not model accuracy.

The retained [September 23 probe](2026-09-23-jev-charged-probe.json) records four
requests and four correct decisions, with no false passes, false failures,
reviews, or unevaluated cases. Its input-token total is 1,787. It is dated local
evidence carried forward, not a fresh inference or billing receipt; the artifact
does not record full provider/model provenance. No new external model request
was made for this release. The earlier [pilot findings and advisory-only
decision](2026-09-22-jev-pilot.md) remain in effect.

This is release bookkeeping for previously deployed work. Creating the tag and
GitHub Release does not itself deploy the Worker. The normal merge-triggered
Pages workflow publishes the updated release label; a new Worker deployment is
not required for the Jev fixtures or test. Existing provider, payment, delivery,
accessibility, and device evidence remains dated and scoped to its source
record; this release does not claim a fresh end-to-end purchase or mail send.

## Recovery

The release preparation changes metadata, documentation, and development-only
evaluation evidence. Reverting this preparation restores the previous release
labels and control set without changing persisted application state. Operational
rollback of any bundled feature still follows its original release evidence and
the [deployment guide](../DEPLOYMENT.md); reverting a label is not a deployment
rollback.
