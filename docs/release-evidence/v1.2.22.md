## Release verification and deployment

The release preparation is limited to metadata, changelog, and this evidence
record. Its pull request requires a fresh hosted Merge Smoke run and all four
dependency audits. Additional release-wrapper results and any unavailable
provider or manual evidence are recorded in the release assets and notes.

The production workflow deploys both Pages and the Worker from the exact merged
release commit. The final source revision, CI run, deployment run, public release
label, and live image/crawl checks are recorded in the
[GitHub release](https://github.com/aindaco1/pool/releases/tag/v1.2.22).
A workflow dispatch alone is not deployment acceptance.

This release does not add checkout, payment, email, campaign-permission, or data
storage behavior. Payment/provider delivery and human assistive-technology
acceptance remain separately scoped evidence; simulated checks do not establish
a fresh real purchase or message delivery.

## Ethical review and recovery

Automatic repository writes remain limited to validated image files and
rebuildable metadata. Source content and concurrent creator edits are protected,
full CI precedes publication, and failed gates leave main unchanged. No new
personal-data collection, messaging, financial authority, or campaign access is
introduced.

The removed historical media branches are retained in a verified local Git
bundle. Image commits and the release preparation remain in Git history. For a
production rollback, redeploy the previous known-good commit through Deploy
Production; metadata version changes require no state migration. Preserve local
configuration, dependencies, Worker state, shared submodules, test fixtures, and
release evidence when clearing reproducible build artifacts.
