# Pool v1.2.3 / Platform cryptographic adoption evidence

## Immutable input

- Previous Pool release: `v1.2.2`.
- Platform pin remains the reviewed immutable `v0.15.0` commit
  `2e79a8d70cb6d30805ea141e53d32f9387441756`.
- Shared implementation remains `@dustwave/worker-core` `0.6.0`; this
  migration consumes an already released module and does not mutate Platform.

## Characterized boundary

Pool's admin authentication now imports SHA-256, HMAC-SHA-256, high-entropy
tokens, cookie parsing, email normalization, and constant-work string equality
from the pinned Platform source. A one-line Pool adapter retains the existing
`secret, data` HMAC call order.

Pool continues to own login-token and cookie formats, expiry policy, session
and CSRF records, origin checks, roles, permissions, routes, KV storage,
credentials, deployment, and rollback. Platform receives no Pool identifiers,
secrets, customer data, campaign content, or deployment authority.

## Security and compatibility evidence

- The consumer contract fixes the expected SHA-256 digest, base64url HMAC and
  random-token shapes, encoded-cookie behavior, normalized email behavior,
  constant-work equality result, and fail-closed rejection of tokens shorter
  than 16 random bytes.
- Existing admin authentication tests retain magic-link exchange, replay
  rejection, fixed session expiry, CSRF/origin enforcement, privacy-minimized
  login history, session review, and explicit revocation coverage.
- Pool's no-`randomUUID` login-history fallback now uses 16 random bytes rather
  than the obsolete 8-byte value. Cloudflare Workers' normal `randomUUID` path
  is unchanged.
